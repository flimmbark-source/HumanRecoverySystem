# Acceptance tests for the pilot release

Run the real browser app against a test database. Unit-test deterministic systems and exercise end-to-end flows with a synthetic seed. Record commands, expected/actual results and any optional credentials needed for the real-provider check.

| Area | Pass condition |
| --- | --- |
| Start and persistence | Create an empty project and a separate synthetic project. Create and edit map data in each. Reload, sign in again, and verify both persist independently. Interrupt a save and recover the draft. Conflicting writes from two sessions show a recoverable conflict instead of silently overwriting. |
| Import and recovery | Import the bundled v0.7 export into a new project. See 6 nodes, 6 edges, 3 linked notes and the workload totals below. Export and reimport a sample with a branched scenario and candidate decisions. Verify preserved ID mappings, revisions and evidence paths. Reject dangling references, duplicate IDs, malformed records and non-finite measurements without any partial change. |
| Map and spacing | At 1440, 1140, 780 and 390 px, use the supplied close-up as reference. No oversized dotted scope frame, clipped graph controls or inspector overlap with essentials. External nodes have labels and local border treatments. On screen, visible labels avoid nodes, other labels and relevant controls. Test long labels, dense links, dragging near a node, collision fallback and undoing Tidy. All relationship types are distinguishable and have a legend. |
| Connection hierarchy | Select “Triage application.” See the transfer, an explicit Coordinator performer, and submitted → ready for placement. Open Performance, Evidence, and Edit deliberately. Change the action, result and state, then confirm the sentence updates across map inspector, preview, timeline and export. Test sender, receiver, third-party and unknown performers. A missing performer must stay unknown. |
| Fieldwork and synthesis | Begin a session and capture a note on the selected connection with inherited source and minimal interaction. Capture another note without a target and attach it later. Link supporting and contradictory notes to an insight, click through to both sources, then create an opportunity and a scenario from it. Verify filters, grouping, sticky category and note anchors. |
| Observation in context | Record two synthetic placement episodes involving the same coordinator. One has a protected conversation and a good match. The other has interruptions and missed details. Capture action, conditions, outcome and hidden effort, with an optional participant clarification. Both episodes remain independently traceable. The app shows task and conditions without rating the person. |
| Open-ended synthesis | Write and save an insight with no evidence, model target, category or template, then reload it. Attach supporting and contradictory observations later and revise or detach links without changing the notes. Use the insight in a recommendation. Verify that the decision view distinguishes observations, interpretation and evidence gaps, and marks a recommendation with insufficient evidence as a hypothesis to test. |
| Strengthening the existing workflow | Starting from the placement episodes, propose protected conversation time and easier routine capacity checks. Identify the practice to preserve, workload changes across roles, the smallest reversible trial, and indicators such as placement quality and after-hours work. Show unknowns and any transferred burden in the comparison. The leadership export expresses findings at a workflow or role level and excludes re-identifying details. |
| Timeline | Replay an explicit route end to end. Scrub and pause at a selected handoff, see the input/output state, and distinguish active and waiting time. Add an alternate route, then a deliberate repeat. The user can choose either route and play/loop safely. An ambiguous, disconnected or incompletely measured route is visibly flagged. |
| Scenario and evidence isolation | Branch baseline → A → B. Change a duration in A, delete e2 in B, and compare B to its parent and the original baseline. Baseline note t1 still links to e2. B has an explicit historical/unavailable attachment state. Removing a required handoff shows affected downstream links and any unreachable outcome. Update the live baseline after branching and make sure both branches retain their original comparison revisions. |
| Opportunity and report | From one insight compare status quo, process change, an existing tool and a bespoke option. Record benefits, human costs, effort, assumptions and a guardrail. Export the current-state map, opportunity sheet and decision brief. Open each in its intended viewer. Include anonymized provenance, show unknowns clearly, and exclude internal-only content. |
| Wide/deep research | Wide run provides citations, a market/practice coverage assessment and a follow-up research question. Deep run uses selected sources and model revision to return structured candidates, a contradiction and a measurement gap. Validate against the import schema. Exercise invalid output, timeout, cancellation, restart and manual import. Drafts must await explicit acceptance. Accept once, retry the same action, and verify one audit entry and no duplicate graph changes. |
| Privacy and operation | Verify project isolation for API, candidate acceptance, jobs and exports. A read-only user cannot mutate. An unauthorized object ID cannot fetch records or enter agent context. Unapproved excerpts do not reach the provider or exports. Restore a synthetic backup and run the production build. |
| Keyboard and mobile | Add/connect nodes through keyboard-accessible controls or list, use visible focus and restore it on drawer close, and verify graph labels and type names are available without relying on hover or color. At 390 px capture a note and inspect the linked edge, then return to the map without losing context. |

## Calculation fixtures

Values below refer to the synthetic workspace and are test inputs, not organizational findings.

- **v0.7 baseline.** The attached export has 80 cases/month. Included durations on e1–e5 are 5, 16, 22, 8 and 12 minutes, once per case. Known effort is 63 minutes/case and 84 hours/month. Select or create the explicit flow route e1→e2→e3→e4. It has 51 active and 120 waiting minutes. Sequential elapsed time is 171 minutes given the fixture's entered values. e5 is an information activity counted in workload but excluded from that selected route. Mark fixture values as unverified sample inputs and retain that distinction in the results.
- **Same volume.** Change e3 from 22 to 10 active minutes. Expect 51 minutes/case and 68 hours/month. At 80 cases/month the modeled release is 16 hours/month. Explicit route elapsed drops to 159 minutes if scenario wait values stay the same. Cash remains unknown without an actual mechanism entered.
- **Changed volume.** Set the scenario to 100 cases/month. Scenario effort becomes 85 hours/month vs baseline 84 hours/month. There is a 1 hour/month increase at the modeled volumes and a 16 hour/month efficiency improvement at the shared baseline volume of 80. Both comparisons must be visible with their denominators.
- **Unknown input.** Clear e3’s duration. Known subtotal becomes 41 minutes/case at baseline; cite one missing included activity. Headline savings and elapsed-time comparison must show incomplete/unknown, even if a known-only subtotal or range is displayed. Set e3 to a sourced zero and confirm zero is treated differently from null. Test numeric ranges and currency/unit mismatches.
- **Cash and people.** Enter a separate, documented 400/month reduction in paid overtime and 80/month recurring service cost in one currency, with 960 one-time implementation cost. Expect 320/month net recurring cash benefit and 3-month simple payback. Add a role-level human-contact concern with missing data. The app must carry the concern and validation plan into the report without inventing a customer-loss value.
